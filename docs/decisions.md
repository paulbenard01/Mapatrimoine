# Decision log

Format: decision. Why. Alternative rejected.

## M0 scaffold

- **Code licence MIT replaces the initial CC0 `LICENSE`** (Paul to confirm). The brief asks for MIT code; data is covered separately by `DATA_NOTICE.md`. Rejected: keeping CC0, which the brief did not ask for.
- **Single repo, `pyproject.toml` at root, package in `pipeline/pci`, site in `web/`.** One `pip install -e .` and one `npm ci` set everything up. Rejected: separate repos or a monorepo tool (gold-plating).
- **Pinned versions released at least ~2 weeks before 2026-10-08** (vite 8.3.0, vitest 5.0.1, maplibre-gl 6.10.0, typescript 6.0.3). Fresh releases are riskier; TypeScript 7 (native port) avoided for the same reason. Rejected: `latest`.
- **`playwright@1.56.1` as dev dependency** because the pre-installed Chromium (`chromium-1194`) matches that release, so no `playwright install`. Rejected: latest Playwright (would need a browser download).
- **`web/.npmrc` sets `legacy-peer-deps=true`.** npm 10.9.4 crashes (`Cannot read properties of null (reading 'edgesOut')`) resolving vitest's optional peers; with the flag `npm ci` works. Rejected: downgrading vitest (same crash on 4.1.11).
- **Vite `base: "./"`** so the build works at any GitHub Pages path (repo name casing). Rejected: hard-coding `/Mapatrimoine/`.
- **Scrubber test scans committed files under `data/`, `web/public/data/` and test fixtures** (via `git ls-files`), matching emails and French/international phone patterns, with negative tests for IDs, coordinates and dates. Rejected: scanning the working tree (would flag the ignored raw text).

## M1 index

- **IDs are normalised, the published form is kept.** The page has `010_67717_..._00116` (Bayonne) and `202 3 _67717_..._005 20` (Rod lo gèp); we strip spaces and repair a 3-digit year to `2010`, storing `id_as_published`. Rejected: dropping them (they are real, published elements).
- **543 elements, 7 themes** on 2026-10-08 (the brief expected ~540). Six IDs appear under two themes; `theme` is the first heading, `themes` keeps both. Rejected: duplicating records.
- **Unpublished flag comes from the official "Liste exhaustive" PDF (July 2024)**, read with `pdftotext -bbox` (pypdf fallback) by attaching each "Fiche dépubliée" marker to the nearest ID above it in the same column. It finds 00004, 00085 and 00442; none of them is listed on the page any more, so the flag is a safeguard. Elements added or unpublished after July 2024 are not covered by the PDF; M2 also checks each fiche's text for the marker. Rejected: bracket heuristics on the flattened text (columns interleave).
- **The list PDF link is matched on the word "Liste"** (word boundary). A plain substring matched "éventail*listes*".
- **One element has no fiche link** (`2008_..._00019`, dentelle du Puy): `fiche_url: null`, never guessed.
- **User-Agent** names the project and its GitHub URL, no personal email.

## M3 recurrence engine

- **Calendar dates are UTC midnights exchanged as `YYYY-MM-DD` strings.** String comparison then orders dates, and no local time zone or DST shift can move a day. Rejected: a date library (one more dependency for ~100 lines of logic).
- **`nextOccurrence` returns the occurrence in progress if `today` falls inside it** (including one that started the previous year, for example the Provençal Christmas season, 4 December to 2 February), otherwise the next start. Rejected: "next start only", which would hide an ongoing festival.
- **"Movable feast" means Easter-relative (`easter_offset`).** `nth_weekday` dates also change every year, but they are not movable feasts in the liturgical sense; the UI shows them as normal dated events. A fixed 29 February only occurs in leap years.
- **`duration_days` counts the first day** (1 = single day), as in the schema.

## M2 fiches and curation

- **Fiche downloads: one request every 5 s, 403 retried after 30 s then 60 s.** After ~10 quick downloads culture.gouv.fr answered 403 to every request (and later took ~100 s per response); the same URLs worked minutes later. All 38 pilot fiches were eventually fetched; nothing was guessed. Rejected: treating 403 as permanent (it was transient here).
- **The committed manifest (`data/fiches-manifest.json`) holds only status, dates, page count and the unpublished marker.** Parsed I.1/I.2/I.4 text goes to git-ignored `data/text/<id>.facts.json`, because the I.1 block of one fiche (Fêtes de l'Ours) yielded a photographer's credit, i.e. a person's name, which the email/phone scrubber cannot catch. Rejected: committing parsed snippets.
- **Two fiche layouts are parsed**: the current UNESCO-style form (I.1, I.2, I.4 headings) and the short 2008-2014 form ("Identification :", "Localisation (région, département, municipalité) :"); for the old form the name stops before "Personne(s) rencontrée(s)", which names private individuals.
- **Unreadable PDF: Biou d'Arbois (`2013_..._00314`)** has fonts without a usable text map (pdftotext and pypdf both return symbols); `extract-text` flags it "unreadable (OCR needed)" and it is not curated. No OCR tool is installed; rejected: adding Tesseract for one file in the pilot.
- **Rule model extended with two optional `nth_weekday` fields** (schema and TS): `offset_days` (Fêtes de Bayonne: Wednesday before the first Sunday of August; Tarasque: Friday before the last Sunday of June) and `from_day` (Gayant: the Sunday after 5 July; Ours: the first Sunday after 1 February). Without them 8 of 30 events could not be expressed. Rejected: new rule types (more code paths) or approximations that are wrong some years.
- **`duration_days` maximum raised to 250** for seasons: the Lourdes marian procession runs every evening April-October (214 days). The Provençal Christmas season (4 December-2 February) crosses the year boundary.
- **Events without a computable rule use `{type: unknown}` with the timing evidence** (Menton: set around school holidays; Nantes carnival: no rule in the fiche; Chinese New Year: lunisolar). They show "date varies" and are not counted in the month strip. Rejected: inventing approximate rules.
- **Some "events" became practices** because their fiche describes no single public date: yole ronde (Martinique), mawlida shenge (Mayotte). With fest-noz, maloya (La Réunion) and chjam'è rispondi (Corsica) that makes 5 practices; falconry and Cilaos embroidery were dropped from the pilot list (fiches downloaded, not curated).
- **Overseas coverage**: events in Guadeloupe (Marie-Galante) and Guyane; practices in Martinique, Mayotte, La Réunion.
- **Where the fiche is dated, the timing says so** (Bayonne's 2010 fiche says early August; the notes flag that recent editions moved) and confidence is lowered to `medium`.
- **Geocoding**: `geo.api.gouv.fr` works without a key (checked 2026-10-08). It has no département/region centre, so `department`/`region` precision uses the mean of commune centres. Connection resets happen; failures are logged and the run continues. `pci build` reads only the committed cache, so CI runs offline.
- **The build checks every quote against the extracted text page when `data/text/` exists locally** (it caught one wrong page number) and counts words (≤ 25). CI cannot do this check because the text is never committed.
- **Summaries were checked against the fiche text**; details that could not be found (e.g. "Ave Maria" at Lourdes, goldsmith flowers in Toulouse) were removed.

## M4 site

- **Inventory first, agenda second (Paul's feedback, 2026-10-08).** Dated events are a small part of the inventory (30 documented of 543 elements), so the default view is the whole inventory: search, theme chips with counts, every element linking to its fiche; the 35 curated ones carry summary, map location and timing. The month strip, "this month" and next-date sorting live in a second view, "Agenda annuel / Yearly events", and next-date badges only show there. Rejected: the first layout, which led with the month strip and only listed the 35 pilot elements.
- **`pci build` also publishes `inventory.json`** (ID, official name, themes, year of inclusion, fiche link) for all 543 published elements: structured facts already listed on culture.gouv.fr. Uncurated entries are shown as "not documented yet" with no place, summary or date (never guessed).
- **Area and distance filters apply to mapped elements only** (uncurated entries have no location); the UI says so. The inventory search ignores case and accents; the agenda view has no search box, so the search does not apply there.
- **Vanilla TypeScript, no UI framework.** One `render()` rebuilds the panel from state and restores focus (by `data-key`), caret and scroll; the results count is a single persistent `aria-live` region updated in place. Rejected: React/Svelte (not needed for ~600 rows).
- **Basemap: OpenFreeMap "positron" style** (checked 2026-10-08: free public instance, no API key, no registration, no cookies; attribution required, shown by MapLibre; may use Cloudflare; IP addresses not stored in access logs except during abuse investigations). Disclosed in the About panel and README. Rejected: Protomaps PMTiles self-hosting (a France extract is hundreds of MB for GitHub Pages) and keyed providers.
- **MapLibre 6 worker bundled through Vite** (`maplibre-gl-worker.mjs?worker&url` + `setWorkerUrl`, `worker.format: "es"`): MapLibre resolves its worker relative to its own module URL, which bundling breaks, leaving a blank map.
- **Markers:** circle = event, diamond = practice, ring (list only) = not documented; colour = theme (Okabe-Ito). Clusters below zoom 8. Selection shows a halo and frames all of an element's places.
- **`?today=YYYY-MM-DD`** overrides the clock (screenshots, tests); otherwise the visitor's local date. Position never enters the URL or storage.
- **Phones:** a List/Map switch comes first; map mode hides search and theme chips so the map fills the screen; filters stay one tap away.
- **Screenshots** (`web/scripts/screenshots.mjs`) proxy only `https://` through `HTTPS_PROXY` (the sandbox proxy refuses plain-HTTP requests to the local preview server) and include a keyboard-only smoke test: search, open, back, switch view, month, area. They are not run in CI (they need network tiles).
- **GitHub Pages workflow** deploys `web/dist` on pushes to `main` only; it needs Settings → Pages → Source: GitHub Actions (manual step for Paul).

## Batch 2: timing checked online (Paul's request, 2026-10-08)

- **Online sources complement the fiches.** Each `timing` now needs a fiche quote (≤ 25 words, page) and/or `web_sources` (URL, publisher, what the page says in our own words, date checked). Preferred sources: town halls, organisers, regional tourism boards; event aggregators (Festivals en France, Unidivers, JDS) only when nothing better was found, with confidence lowered. Personal contact details seen in listings (organisers' phones and emails) are never copied. Rejected: verbatim web quotes, which we cannot re-check in CI.
- **New rule `{type: dates, occurrences: [...]}`** for editions announced by organisers when no stable rule exists or the fiche is out of date: Fêtes de Bayonne (fiche of 2010 says early August; the city announced 14-18 July 2027), Fête du Citron (13-28 Feb 2027), Lunar New Year (6 Feb 2027), Grand Pardon de Chaumont (24 June 2029). Once all listed dates are past the element shows "date varies" again, so these entries need yearly refreshing (M5 automation).
- **Optional `every_years` + `reference_year`** on rule types for festivals that are not annual: Boulogne Fête de la Mer and the Ringueta in Sarlat (even years).
- **Rules inferred from several dated editions are marked `medium`** and say so in the notes (Dax: Wednesday-Sunday ending the first Sunday from 15 August, matches 2025 and 2026; Vaisakhi in Bobigny: Sunday on or after 13 April, matches 2022, 2024, 2026; Boulogne: Thursday-Sunday ending the first Sunday from 13 July, matches 2024 and 2026).
- **Batch 2 fiches were also downloaded and read** (same polite fetcher) so summaries, kind and domain still rest on the official text and the unpublished check still applies.
- **Not added (no usable current date):** Carnaval des Deux-Rives (Bordeaux; last dated edition 2010), Carnaval de Périgueux (Sundays in February or March, varies), Lo Cese de Montaren and the Pornic spring parades (dates vary each year), Saint-Léon in Marseille and the Saint-Ferme living crib (nothing current online).
- **Three entries rest on online sources only** (`fiche_read: false`): Saint-Léon in Marseille, the Mexican Candelaria in Paris and the Fête de la Mer in Capbreton, whose PDFs kept failing to download (timeouts and 403s over several hours). Paul asked to use online information for them. Two cite PCI Lab, the ministry's collaborative platform that publishes the inventory texts. The build requires `web_sources` for such entries, `source.fetched_at` is null, and the detail panel says the official fiche could not be consulted.

## Batch 3: every element on the map, with images (Paul's request, 2026-10-08)

- **Why most elements were invisible:** only the 76 curated elements had places, because the inventory page lists names and links only; places live in each fiche. Paul asked for the map to show everything, with several pins when an element spans several places, and a picture for each element.
- **Places come from PCI Lab first.** PCI Lab (pci-lab.fr), the online edition of the inventory run by the ministry with the CIRDOC ethnopôle, embeds a point per fiche in its map page and shows each fiche's "Localisation (région, département, municipalité)" field. `pci fetch-pcilab` reads them politely (cached, 1.5 s apart) into `data/raw/pcilab.json`, which stays local: PCI Lab titles sometimes name private craftspeople and its fiche pages carry contact details. Rejected: committing that file, and pinning PCI Lab's single point per element (it collapses multi-place elements and sometimes sits on the ministry in Paris for national ones).
- **`data/places.yaml` is written by hand from those fields**: one or more places per element (commune, département, region, a named historical region such as "Aquitaine" or "Pays basque", or an explicit point for New Caledonia and French Polynesia, which the COG gazetteer does not cover). `~` places are marked `approximate`: a pin on a pays's main town, labelled with the pays ("Trégor", "Pays bigouden"). Where PCI Lab had no usable localisation (about 90 elements, mostly recent fiches), the official fiche was read online and its "Lieu(x) de la pratique" section turned into places, cited as `sources`. Only place names were taken, never the people named next to them.
- **National or diffuse practices** get pins where the fiche says the practice concentrates (e.g. tango festivals: Tarbes, Toulouse, Albi…; carillons: the five regions the fiche names). When the fiche names no place at all (baguette, bistrots, butchery, glass beads, demoscene, savate, coachbuilding), one pin labelled "France entière" sits on PCI Lab's own point (or the centre of France) with precision "approximate", so it stays visible without claiming a place.
- **Geocoding runs locally** from cached per-département commune lists (`geo.api.gouv.fr/departements/{code}/communes`, one request each), which also exposes merged communes (Brantôme → Brantôme en Périgord, Accolay → Deux Rivières): labels keep the historical name.
- **Map:** documented elements keep filled circles/diamonds; the others are theme-coloured rings, drawn underneath. Clusters are donut charts of their themes (HTML markers over an invisible click layer) so the map shows what kind of heritage is where. Cluster numbers count markers, not elements (an element with eight places counts eight).
- **Images: Wikimedia Commons first, fiche images second.** Commons files were found through its search pages (its API rate-limits this sandbox's IP), picked by hand from the results (only files that clearly show the element, its place or its practice), and their author and licence read from the file page. Elements without a suitable Commons file show the fiche image published on PCI Lab, *linked from pci-lab.fr rather than copied*, credited to the inventory fiche and linking to its PCI Lab page: PCI Lab's legal notice says some fiche content is under copyright with strict reuse rules, and hotlinking keeps the image on the ministry's server. Rejected: extracting images from fiche PDFs into the repository (copyright; no per-image credit). Images load from Wikimedia and PCI Lab servers, which see visitors' IP addresses; disclosed in the About panel, README and data notice.
- **Coverage at the end of batch 3:** 543/543 elements on the map (946 pins for the 467 non-curated ones); pictures for 488: 126 Wikimedia Commons files and 362 fiche images via PCI Lab. 55 have none: Commons has nothing that shows them and PCI Lab has no image for them (mostly 2025-2026 fiches and Breton or Norman games whose PCI Lab banner is a placeholder). Their fiche PDFs do contain photos, but copying those into the repository would republish copyrighted fiche content, so that waits for Paul's decision.
- **Commons uploads under 400 px** (thumbnails the ministry uploaded) give way to the larger fiche image. A Purim spiel photo from a New York archive was rejected (not the practice in France). Credits that read badly (wiki signatures, "Unknown authorUnknown author") are cleaned; a few are set by hand in the picking script.

## Batch 4: photos from the fiches (Paul's request, 2026-10-08)

- **Paul asked to add fiche photos for the 55 elements without a picture, accepting the copyright question.** The fiches were downloaded five at a time (through the WebFetch tool, which avoids culture.gouv.fr's 403 bursts; two that kept failing, Gignac's senibelet and Larrau's sendatu, are left without a picture). Photos were extracted locally with `pdfimages`, every candidate was looked at on a contact sheet, and one was chosen per element: preferably the object, gesture or event rather than a close portrait. One fiche's only usable photo showed a child's face; it was not used.
- **Result: 42 photos** in `web/public/img/fiches/<id>.jpg` (≤ 960 px, JPEG, re-encoded so no EXIF or other metadata survives, 1.4 MB in total), `source: fiche` in `data/images.yaml`, credited "Photo from the inventory fiche (Ministry of Culture); credits in the fiche" with a link to the fiche. Photographers' names are not repeated (hard rule 1); the fiche link carries the credit. Small originals (some fiche photos are 200 px wide) are shown at their own size, never upscaled.
- **Still without a picture (13):** 10 older fiches that contain no photos at all (text-only fiches of 2008-2012, mostly single craft workshops and Breton games), the two fiches that would not download, and the African hairdressing fiche (only photo shows a child). DATA_NOTICE.md says rights holders can ask for removal.
- Rejected: hotlinking the PDF (no image URL exists) and rendering whole fiche pages as images (would republish fiche text).

## M6: mediation sheets

- **One YAML per sheet in `data/mediation/`, separate from `data/curated/`.** Sheets are written and reviewed on their own schedule, by a mediator rather than a data curator; keeping them apart keeps the element schema small. The build rejects a sheet whose element has no curated summary, since the sheet prints that summary. Rejected: generating questions from templates (they read as quizzes, not conversation starters).
- **FR and EN side by side on one page**, not a language toggle: a mediator with a mixed group hands out one sheet. The sheet reuses the element's summary, picture, places, rule and next date, so nothing is written twice. Print CSS shrinks type to fit one A4 page; the browser's "Print / Save as PDF" makes the PDF, so no PDF library and no generated files.
- **Exactly 3 questions and 5 terms**, enforced by the schema (the brief's format); definitions capped at 30 words so the table stays printable. Everything is `lang_review: draft`, `review_status: unreviewed` and the printed sheet says so until Paul reviews it.

## M7: short summaries for the rest of the inventory

- **A light tier before full curation.** A curated record needs the fiche PDF, timing evidence checked on its page and web sources; doing that for 467 elements is many sessions. So every other element first gets `data/summaries.yaml`: its kind and a one- or two-sentence own-words summary (FR/EN), shown and searchable on the site with a "short description only" note, its source linked and `review_status: unreviewed`. Rejected: loosening `data/curated` (it would blur which elements have checked timing), and leaving 86 % of the inventory without any description.
- **Source: the fiche text PCI Lab publishes.** PCI Lab (ministry and CIRDOC) carries the full fiche text for 446 of them; it was already in the local download cache from the places work, so no new requests were needed. The remaining ones are read from the official fiche online. The text stays local (git-ignored); summaries never name people, private workshops or companies, and give no dates beyond what the fiche states ("each August").
- **Kind rule:** `event` only for a datable public occasion (festival, procession, carnival, pilgrimage, fair); crafts, games and sports (even with yearly tournaments), dances, music and life-cycle rituals are `practice`. Borderline cases (e.g. a sword dance performed once a year) are listed for review. Short-summary events stay off the agenda until their timing is curated.
- **Review report.** `pci review` writes `docs/review.md` from the committed data (coverage, documented elements by lowest timing confidence, short summaries) with links to each element and sheet; a test fails when it is stale, so the report is always true. Paul reviews by editing the YAML flags.

## M5: announced dates from DATAtourisme

- **DATAtourisme's daily open export, not an API.** data.gouv.fr publishes DATAtourisme (ADN Tourisme, Licence Ouverte 2.0) every day, including a CSV of all listed events (~80,000 rows, ~60 MB). Downloading it needs no account, key or secret, so the scheduled build can fetch it and nothing sensitive sits in the repository or the browser. Rejected: OpenAgenda (an API key per account and reads per agenda; its open-data licence is not named in its developer docs) and DATAtourisme's own API (key and form), which add secrets for no extra coverage.
- **Matching by hand-written terms and distance.** `data/announced.yaml` gives each documented event a few search terms (e.g. "carnaval de limoux") and a radius around its places; a listing matches when its folded title contains a term and it lies within the radius. Exhibitions are skipped (about the tradition, not the event). Generic terms such as "saint-jean" get a small radius. Rejected: fuzzy matching on the whole title (too many false positives among 80,000 listings).
- **What is kept:** title, periods, commune, the first web link from the contacts field and the publishing tourist office. Contacts, addresses and descriptions are dropped because they can name people. The site shows the dates as "announced", credits DATAtourisme and its licence, says the match is automatic and asks visitors to check with the organisers; periods that have ended are hidden by the browser's clock.
- **Refresh:** the Pages workflow runs daily at 05:17 UTC (after the ~03:00 export); if the download fails it keeps the committed snapshot and warns. On 2026-10-09 the export matched 9 of the 71 documented events (most 2027 editions are not listed yet).
